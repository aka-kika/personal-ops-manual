How a page says what to check

A new list in the page's frontmatter, checks. One line per fact, written by the operator when the page is verified. Pages without it are simply not checked. Obsidian shows it as a normal list property.

checks:
  - app "Personal Ops Manual" 2.2.5 notarized
  - mcp personal-ops-manual
  - port 4319 node
  - launchd com.akakika.socials
  - cli gh 2.103.3
LineWhat the app looks at (read only)
app <name> [version] [notarized]/Applications/<name>.app: its version in Info.plist; spctl for notarized
mcp <server>~/.claude.json, user and project scopes (faster than claude mcp list, which starts every server)
port <number> [process]lsof: is something listening, and which process
launchd <label>launchctl print gui/501/<label>: loaded, and running or not
cli <name> [version]the CLI found on PATH, run with --version only

Safety: the page text never becomes a shell command. Each kind runs one fixed program with fixed arguments; names are passed as arguments, not typed into a shell.

What "Report" writes

One line in _inbox/reports.md, the same shape report_change writes, so the operator handles it like any report. Drift never edits a page. A finding already reported (an open line for the same page and claim) shows "Reported" instead of the button.

- [ ] 2026-11-06 01:20 UTC · drift · page: Personal Ops Manual · page says "app 2.2.4"; now 2.2.5 · evidence: /Applications/Personal Ops Manual.app Info.plist, checked 03:20

When it checks

  • When the Drift row is opened, and with the "Check now" button. Takes about 2 seconds for 40 checks.
  • The sidebar number is from the last check, so it is visible without opening Drift.
  • "Couldn't check" (for example a CLI that is not installed) is shown grey, not as drift.
